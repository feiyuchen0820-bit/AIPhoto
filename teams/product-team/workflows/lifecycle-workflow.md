# 产品全生命周期工作流

## 阶段流转图

```
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 0: 前期调研 (1-2 天)                     │
│  Pre-Research Agent → 快速扫描 → 竞品盘点 → 可行性评估 → 立项建议  │

└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 0.5: 立项决策 (PM Agent)                 │
│              PM Agent 评审可行性报告 → 决定立项/暂缓/放弃          │
│                        交付物：立项决定书                          │
└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 1: 产品定义 (3-5 天)                     │
│  Research Agent → 市场调研 → 竞品分析 → 用户画像 → 产品定位       │

└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 2: 产品设计 (3-5 天)                     │
│    Design Agent → PRD 撰写 → 功能设计 → 原型思路 → 需求评审       │
│                        交付物：PRD 文档                            │
└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 3: 技术架构 (2-4 天)                     │
│  Architecture Agent → 技术选型 → 架构设计 → API 设计 → 架构评审   │
│                        交付物：架构文档                            │

                                │
                                ▼

│     Dev Agent → 代码框架 → 功能实现 → 单元测试 → Code Review     │

                                │

│                    Phase 5: 测试 QA (3-5 天)                      │
│     QA Agent → 测试计划 → 测试执行 → Bug 修复 → 测试报告         │
│                        交付物：测试报告                            │
└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 6: 上线部署 (1-2 天)                     │
│   DevOps Agent → CI/CD → 灰度发布 → 全量发布 → 监控配置          │
│                        交付物：线上产品                            │
└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 7: 运营追踪 (持续)                       │
│    Ops Agent → 数据监控 → 用户反馈 → 分析报告 → 迭代建议         │
│                        交付物：运营报告                            │
└──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Phase 8: 迭代规划 (循环)                       │
│           PM Agent 收集反馈 → 优先级排序 → 回到 Phase 2/3         │
│                        交付物：迭代计划                            │
└──────────────────────────────────────────────────────────────────┘
```

## 阶段准入条件

| 阶段 | 准入条件 | 审批人 |
|------|----------|--------|
| Phase 0 | 产品想法，团队背景 | PM Agent |
| Phase 0.5 | 可行性报告完成 | PM Agent |
| Phase 1 | 立项通过，资源到位 | PM Agent |
| Phase 2 | 调研报告通过评审 | PM Agent |
| Phase 3 | PRD 文档通过评审 | PM Agent |
| Phase 4 | 架构文档通过评审 | Architecture Agent + PM |
| Phase 5 | 代码通过 Code Review | Dev Agent + QA Agent |
| Phase 6 | 测试报告通过，无 Critical Bug | QA Agent + PM Agent |
| Phase 7 | 发布成功，监控正常 | DevOps Agent |

## 阶段退出条件

| 阶段 | 退出条件 | 交付物 |
|------|----------|--------|
| Phase 0 | 可行性报告完成 | 可行性报告、立项建议 |
| Phase 0.5 | 立项决策完成 | 立项决定书 |
| Phase 1 | 调研报告评审通过 | 市场调研报告、竞品分析、用户画像 |
| Phase 2 | PRD 评审通过 | PRD 文档、功能清单、原型说明 |
| Phase 3 | 架构评审通过 | 架构文档、API 规范、数据库设计 |
| Phase 4 | 代码冻结 | 源代码、单元测试、开发文档 |
| Phase 5 | 测试通过 | 测试报告、Bug 清单 |
| Phase 6 | 发布完成 | 线上产品、监控配置 |
| Phase 7 | 持续运营 | 运营报告、迭代建议 |

## 并行任务

以下任务可以并行执行：

- Phase 4 开发中，QA Agent 可提前编写测试用例
- Phase 4 开发中，DevOps Agent 可提前配置 CI/CD
- Phase 5 测试中，Ops Agent 可提前准备数据看板

## 风险管理

### 常见风险

| 风险 | 阶段 | 缓解方案 |
|------|------|----------|
| 需求变更 | Phase 2-4 | 变更控制流程，评估影响 |
| 技术难点 | Phase 3-4 | 技术预研，备选方案 |
| 进度延期 | 任何阶段 | 缓冲时间，优先级调整 |
| 质量不达标 | Phase 5 | 延长测试，修复 Bug |

### 升级机制

```
Agent 发现风险 → 记录到 blockers.md → PM Agent 评估 → 
├─ 低风险 → Agent 自行处理
├─ 中风险 → PM Agent 协调资源
└─ 高风险 → 升级人类决策者
```

## 沟通机制

### 每日站会（模拟）
- 各 Agent 更新状态文件
- PM Agent 汇总生成日报
- 识别阻塞问题

### 阶段评审
- 阶段结束前 1 天发起评审
- 相关 Agent 参与
- PM Agent 主持

### 紧急沟通
- Critical Bug → 立即通知 PM + Dev + QA
- 线上故障 → 立即通知 PM + DevOps + Ops
